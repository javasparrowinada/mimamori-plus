見守りプラス｜AIレポート仕様

概要

AIレポートとは

隔週月曜、メールで届く「あかりからの手紙」。使用状況に応じて文面が自動で変わる。

項目内容
チャネルメールのみ（LINEでは送らない。LINEは緊急通知・日常通知に専念）
頻度隔週1回（隔週月曜 朝10時）
文面方式テンプレートエンジン（AI APIは使わない。テンプレートの組み合わせで実現）
語り手
森川あかり（サポート担当店長。「あかりからの手紙」の温度感）
構成4ブロック：①挨拶 → ②総評 → ③使用データ → ④締め
LINE相談リンク先全メール共通の「LINEで相談する」ボタンのリンク先URLは以下で固定：
https://liff.line.me/2006093695-yWKodwlG/landing?follow=%40741gbrqo&lp=MbOxbS&liff_id=2006093695-yWKodwlG
理論組み合わせ総数: 1（挨拶＝全月共通の固定文）× 9（総評＝3条件×V1/V2/V3）× 36（締め＝12月×V1/V2/V3）= 324通り（情緒メッセージ）＋ 使用データは実数値で自動表示
4ブロック構成

メールの中身はどうなっているか

4つのブロックを順に並べてメールを構成する。
②総評だけがユーザーの活動データで変わり、残りは季節で変わる。

①

挨拶 ─ 名乗り（全月共通の固定文）

全月共通の固定文 1テンプレート

名乗り＋今回のレポートをお届けするお声がけの固定文。季節のひと言は「④締め」側でまとめて出し分ける。

G-01-1 {{ユーザー名}} 様

ソラリッチ店長の森川あかりです。
いつも見守りプラスをご利用いただき、ありがとうございます！

今回の見守りレポートをお届けします😊
②

総評 ─ 今回のようす（レポートの核心）

1軸 × 3段階 × V1/V2/V3 9テンプレート

USB/AC/LEDライトの使用頻度で3段階（よく使っている／ときどき使っている／使っていない）に判定し、文面のトーンが自動で変わる。詳細は下の「1軸判定」セクションへ。

③

使用データ ─ 実数値（通知ログから自動集計）

通知ログの件数をそのまま表示 自動生成

情緒的なメッセージ（②）と実数値（③）の両方があって、バランスの良いレポートに。

注記：ここで言う「通知ログ」「通知#4〜#6」は、デバイスの動作イベントを記録した集計用の内部データを指します。ご家族のLINEに届く「通知」そのものではなく、その素材となる記録です（AIレポートはこれを集計して文章化します）。以降のセクションの「通知」も同じ意味で使っています。
項目データ元表示例
コンセント接続常時接続が前提接続中 ✅
LEDライト通知#LED（LEDライト通知）のCOUNT
※SOSとは別で照明としてのLEDライト使用		5回
AC給電通知#5（AC給電通知）のCOUNT8回
USB給電通知#4（USB給電通知）のCOUNT12回

※ 0回の項目は行ごと非表示。「あるものだけ書く。ないものを書くと寂しくなる」の方針。全部0回ならコンセント接続だけ残る。

④

締め ─ 季節の結び＋{{ニックネーム}}様への言及

月別 × V1/V2/V3 のローテーション 36テンプレート

12ヶ月 × 各月3バリエーション = 36通り。季節に合わせた結びの一言と、{{ニックネーム}}様（お母さん・おばあちゃん等）へのお声がけを添える。V1/V2/V3 は送信のたびにローテーション。

月テーマの例
1月年始のご挨拶、寒さと防寒
4月桜🌸、春の便り
7月暑さ、水分補給、扇風機・熱中症対策
9月防災月間、敬老の日、涼しさ
12月年末年始、良いお年を

②総評はどう出し分けるか

1つの軸で3段階に判定。各条件に V1/V2/V3 の言い回し3バリエーション = 計9テンプレート。

🔌 軸1：USB/AC/LEDライトの使用頻度

通知が送信された回数で判定。通知#4 (USB給電) + #5 (AC給電) + #LED (LEDライト) の合計を集計。

よく使っている

通知#4 + #5 + LED の
合計 ≧ 10回

ときどき使っている

通知#4 + #5 + LED の
合計 = 1〜9回

使っていない

通知#4 + #5 + LED の
合計 = 0回

除外項目：コンセント接続は判定軸から除外（常時接続が前提。外れたらアラート#1でリアルタイム通知済み）。
集計方法：通知ログからCOUNTで取得。追加開発不要。
